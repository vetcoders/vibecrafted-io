01 · Oczy

loctree

Strukturalna inteligencja codebase. Mapuje pliki, zależności, huby i blast radius zanim agent dotknie jakiejkolwiek zmiany.

Otwórz warstwę
  • Mapuje repozytorium zanim ktokolwiek zacznie je zmieniać.
  • Chroni przed ślepymi refaktorami i błędnym poczuciem pewności.
  • Używaj go, gdy ryzykiem jest struktura.
02 · Pamięć

aicx

Odzyskiwanie decyzji dla warstwy agentowej. CLI `aicx` / serwer `aicx-mcp` indeksują decyzje, intencje i wyniki, żeby sesje mogły odtworzyć co zostało ustalone i dlaczego.

Otwórz warstwę
  • Odzyskuje wcześniejsze decyzje, zamiary i kontekst.
  • Utrzymuje ciągłość pracy między sesjami.
  • Najbardziej przydatny przy zadaniach rozciągniętych w czasie.
03 · Review

prview

Ustrukturyzowane artefakty review. Zamienia zmiany w kodzie w trwałe findingi, które mogą czytać kolejne agenty i ludzie.

Otwórz warstwę
  • Pakietuje review w trwałe findingi i czytelny gate.
  • Zamyka lukę między terminal dumpem a realnym artefaktem.
  • Używaj przed merge i przed release.
04 · Uszy

ScreenScribe

Narracyjny review runtime. Zamienia nagrania ekranu z komentarzem w ustrukturyzowane findingi o realnej powierzchni produktu.

Otwórz warstwę
  • Zamienia nagrania ekranu w ustrukturyzowane dowody.
  • Patrzy na to, co użytkownik naprawdę zobaczył.
  • Najlepszy, gdy trzeba zobaczyć prawdę runtime.

Marbles

Odszumiaj aż koło się zapełni

Agenci AI to stochastyczne papugi. Każda generacja wprowadza szum. Nie da się tego obejść promptem. Iterujesz.

Izomorfizm

Dyfuzja obrazu szum → odszumienie × N → obraz
Dyfuzja kodu chaos → redukcja_entropii × N → produkt
Krok 0: Czysty szumKrok 1: InitKrok 2: ImplementacjaKrok N: DoU < próg = DoD

Nie ma ustalonej liczby pętli. Pętla działa aż P0=P1=P2=0 i koło się wypełni. Wczesne pętle robią korekty strukturalne, późne pętle dopracowują detale.

DoU

Definicja niezrobionego

Agenci AI rozwiązali najtrudniejszą część tworzenia oprogramowania: sprawienie, żeby rzecz działała. Nie rozwiązali jeszcze drugiej najtrudniejszej: sprawienie, żeby była osiągalna.

Problem rzadko dotyczy jakości kodu. To brutalna przestrzeń między działającym systemem a produktem, który obcy mogą odkryć, zainstalować, któremu zaufają i za który zapłacą.

Diagnostyka założyciela:

  • + Testy przechodzą
  • + Architektura jest solidna
  • + README istnieje
  • – Nikt nie znajdzie tego w Google
  • – Nikt nie zainstaluje bez toolchaina
  • – Nikt nie może za to zapłacić

Punkty 4–6 to Definicja Niezrobionego. Faza 3 wymusza wejście systemu na rynek.

Zainstaluj silnik release'u. Uruchom pętlę.

Zbootstrapuj control plane przez publiczną ścieżkę instalacji, zweryfikuj lokalną powierzchnię i wejdź w pierwszy workflow prowadzący do realnego shipu.

01

Zbootstrapuj control plane

Zainstaluj framework lokalnie przez publiczną ścieżkę bootstrapu. Jeśli chcesz browser-guided installer, użyj make vibecrafted w repo.

$ curl -fsSL https://vibecrafted.io/install.sh | bash
02

Wejdź przez command deck

Główne drzwi wejściowe to teraz vibecrafted. Codzienne powierzchnie skilli są dostępne jako bezpośrednie komendy vc-*.

$ vibecrafted help && vibecrafted init claude
03

Napędzaj prawdziwą pracę

Zbadaj codebase, odtwórz ground truth i deleguj implementację do równoległych agentów — wszystko w jednym pipeline.

$ vibecrafted workflow claude --prompt "Plan and implement auth module"
04

Konwerguj aż przestanie kłamać

Pętla marbles znajduje to, co wciąż jest źle i eliminuje to. Każde przejście wyostrza powierzchnię.

$ vibecrafted marbles codex --count 3 --depth 3

Referencje

Ground Truth i inspiracje

Poniższa bibliografia rozszerza listę manifestu o wpływy modelowania strukturalnego i konwergencji wyłonione ponownie w wewnętrznej pracy groundingowej AICX.

  1. Morris, K.; Böckeler, B. (2026). Humans and Agents in Software Engineering Loops; Harness Engineering; Context Engineering for Coding Agents. Thoughtworks / Martin Fowler.

    Framing why-loop / how-loop, projektowanie harnessów i dyscyplina workflow prowadzonego przez człowieka stojące za SHACE i rolą operatora.

  2. Gong, L.; Elhoushi, M.; Cheung, A. (2024). AST-T5: Structure-Aware Pretraining for Code Generation.

    Wątek pretreningu świadomego struktury stojący za insistencją 𝚅𝚒𝚋𝚎𝚌𝚛𝚊𝚏𝚝𝚎𝚍., że modele nie powinny pisać do repo na ślepo.

  3. Guo, D. et al. (2021). GraphCodeBERT: Pre-training Code Representations with Data Flow.

    Komplementarny wynik świadomy struktury, który wzmocnił argument za eksternalizowanym kształtem kodu, mimo że GraphCodeBERT modeluje przepływ danych, a nie AST.

  4. Cunningham, W. (1992) i późniejsza literatura o długu technicznym.

    Konceptualny przodek DoU: działający kod to nie to samo co zdrowy, godny zaufania, gotowy do wysyłki system.

  5. CEGIS / synteza prowadzona kontrprzykładami i późniejsza literatura o optymalizacji prowadzonej kontrprzykładami.

    Linia konwergencji za Marbles: pętla, inspekcja awarii, dodanie kontrprzykładów, redukcja przestrzeni programów, powtarzanie aż powierzchnia przestanie kłamać.

  6. VetCoders (2026). Manifest 𝚅𝚒𝚋𝚎𝚌𝚛𝚊𝚏𝚝𝚎𝚍..

    Źródło pierwotne dla SHACE, Marbles, Loctree Mapping, PSCD i założycielskiej Definicji Niezrobionego jako oryginalnych konceptów 𝚅𝚒𝚋𝚎𝚌𝚛𝚊𝚏𝚝𝚎𝚍..
