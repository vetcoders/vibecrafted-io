Marbles

Denoise Until the Circle Is Full

AI agents are stochastic parrots. Every generation introduces noise. You cannot prompt your way out of it. You iterate.

The Isomorphism

Image diffusion noise → denoise × N → image
Code diffusion chaos → reduce_entropy × N → product
Step 0: Pure noiseStep 1: InitStep 2: ImplementStep N: DoU < threshold = DoD

There is no fixed loop count. The loop runs until P0=P1=P2=0 and the circle is full. Early loops make structural corrections; late loops make smaller refinements.

DoU

The Definition of Undone

AI agents have solved the hardest part of software creation: making the thing work. They have not yet solved the second hardest part: making the thing reachable.

The gap is rarely code quality. It is the brutal space between a working system and a product that strangers can discover, install, trust, and buy.

The Founder's Diagnostic:

  • + Tests pass
  • + Architecture is sound
  • + README exists
  • – Nobody can find it from Google
  • – Nobody can install it without a toolchain
  • – Nobody can pay for it

Items 4–6 are the Definition of Undone. Phase 3 forces the system into the market.

Ground Truth & Influences

The bibliography below extends the manifesto list with the structural-modeling and convergence influences surfaced again in internal AICX grounding work.

  1. Morris, K.; Böckeler, B. (2026). Humans and Agents in Software Engineering Loops; Harness Engineering; Context Engineering for Coding Agents. Thoughtworks / Martin Fowler.

    The why-loop / how-loop framing, harness design, and human-guided workflow discipline behind SHACE and the operator role.

  2. Gong, L.; Elhoushi, M.; Cheung, A. (2024). AST-T5: Structure-Aware Pretraining for Code Generation.

    The structure-aware pretraining thread behind 𝚅𝚒𝚋𝚎𝚌𝚛𝚊𝚏𝚝𝚎𝚍.'s insistence that models should not write into a repo blind.

  3. Guo, D. et al. (2021). GraphCodeBERT: Pre-training Code Representations with Data Flow.

    A complementary structure-aware result that reinforced the case for externalized code shape, even though GraphCodeBERT models data flow rather than AST.

  4. Cunningham, W. (1992) and later technical debt literature.

    The conceptual ancestor of DoU: working code is not the same thing as a healthy, trustworthy, shippable system.

  5. CEGIS / counterexample-guided synthesis and later counterexample-guided optimization literature.

    The convergence lineage behind Marbles: loop, inspect failure, add counterexamples, reduce the plausible program space, repeat until the surface stops lying.

  6. VetCoders (2026). The 𝚅𝚒𝚋𝚎𝚌𝚛𝚊𝚏𝚝𝚎𝚍. Manifesto.

    Primary source for SHACE, Marbles, Loctree Mapping, PSCD, and the founder-grade Definition of Undone as original 𝚅𝚒𝚋𝚎𝚌𝚛𝚊𝚏𝚝𝚎𝚍. concepts.
